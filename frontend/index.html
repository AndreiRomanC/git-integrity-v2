Help
What everything in this app does, in plain terms.

      

        

          Project Explorer
          
Browse your repository like a file manager. Double-click a folder to open it. Submodules (◇) look like folders but are actually separate Git repositories nested inside yours.

          
Status colors next to a file/folder:

          
    
            
  • Modified locally — has real uncommitted edits.
    • 
            
  • New, untracked — a file Git doesn't know about yet.
    • 
            
  • Not pushed yet — fully committed, but that commit hasn't reached the server. Nothing to commit here — it needs a push.
    • 
            
  • New version (submodules only) — the submodule has a new commit, already recorded in the project, just not pushed to its own server yet.
    • 
          

        

        

          Working tree (Commit)
          
Click "Working tree" in the sidebar (or "Changes in folder" in the toolbar) to see everything changed. Opening it auto-stages everything in scope, so Commit works immediately — untick anything you don't want included, then write a message and hit Commit.

          
"Commit this item" in a file/folder's details panel commits just that one item, same idea, scoped to it.

          
The "Default commit message" field at the top pre-fills every commit box for you — handy when several commits in a row are against the same ticket. It remembers your last 10 messages (click the field to see them again) and shows a small Polarion link when the text matches P:ID.

        

        

          Submodules — Pull, Push, Force push
          
A submodule is its own independent Git repository. Its actions work on that repository and its own remote, separate from your main project.

          
    
            
  • Pull submodule — fast-forward only. Brings in new commits from its remote; refuses safely if that would need a real merge.
    • 
            
  • Merge branch… — brings another branch into the submodule's current one, with conflict resolution if needed. Stays entirely local until you push.
    • 
            
  • Push submodule — sends the submodule's own commits to its own remote. Shows you the exact list of commits before sending. Refuses if the remote has commits you don't have yet.
    • 
            
  • Force push submodule — overwrites the submodule's remote branch with your local history, no matter what. Anything on the server that isn't in your history is permanently lost. Only safe if nobody else uses that remote. Requires double confirmation.
    • 
            
  • Commit submodule — commits uncommitted changes inside the submodule. The moment that commit exists, the main project automatically records the new version too — no manual "Change version" step needed, push or not.
    • 
            
  • Change version — switches the submodule to a different branch, tag, or commit.
    • 
            
  • New branch… — creates and switches to a new branch inside the submodule, from its current commit.
    • 
          

        

        

          Branch Map (the commit graph)
          
Shows commit history as a graph. Pick a branch as "Primary" (top of the graph) — its own history stays on the main lane; anything from another branch not reachable from it gets a side lane, branching off from where the two share history.

          
A dashed ring around a dot marks a branch point (a common ancestor two labels share). "N commits ahead of X" tells you how far a branch has diverged. Stash entries show as a small "⇕ stash" pill on their base commit — never mixed into real history.

        

        

          Merge branch & conflicts
          
"Merge branch…" brings another branch's commits into your current one — entirely local, nothing is pushed automatically. If it can fast-forward, it just does. If it merges cleanly, it commits automatically. If there are real conflicts, a dialog lists each file — "Keep mine", "Keep theirs", or "Edit manually" (opens the file with the standard conflict markers) — then "Complete merge" once everything's resolved. "Abort merge" cancels and restores exactly how things were before.

          
The same conflict dialog opens automatically if popping a stash couldn't apply cleanly (see Stash below) — there it says "Stash conflicts" instead, and finishing just says "Done" (no merge commit needed; the resolved files become your regular working-tree changes).

        

        

          Unpublished commits (Publish)
          
Shows local commits not yet on the server, for the main project only (not submodules — use "Push submodule" for those). Every commit listed here is checked by default; unchecking one also unchecks everything newer than it (Git can only push a continuous range, so that's the only valid way to "leave some out"). Click "Publish branch" to send what's checked.

        

        

          Local ↔ Remote (Commander)
          
Compares your working copy against a chosen remote snapshot, file by file, without checking anything out. Useful to see exactly what differs before deciding what to do about it.

        

        

          Stash
          
The stash is a temporary holding area — changes you put there are set aside and won't be part of any commit until you bring them back. "Stash work" (top toolbar) sets aside everything uncommitted, leaving your working folder clean — useful for switching tasks without committing half-finished work.

          
"Pop stash" opens the full Stashes list — a plain list of every entry and the files it contains. Click "⇈ Restore" next to any file to bring back just that one; it disappears from the list once restored (it's in your working tree now, nothing more to do there). The rest of the stash is untouched, so come back for other files whenever you want. "Drop entire stash" discards everything still left in that entry, for good.

          
To set aside just one file instead of everything, use the "⇕ Stash" button next to it in the Working tree drawer, or "⇕ Stash this file" in that file's own details panel (select it in Explorer to see it) — either way, only that file is stashed; every other change stays untouched.

          
Stashes show up as small ⇕ markers in the Branch Map on the commit they were based on, not as real history — click one to expand it and see exactly which files it contains, before you decide to bring it back.

          
If "Pop stash" can't apply cleanly (the file changed since you stashed it), it doesn't fail or lose anything — it opens the same conflict-resolution dialog used for merges, and the stash itself is kept until you finish (or explicitly discard and keep it for later).

        

        

          Command Console (⌘ or Ctrl/Cmd+K)
          
Commands tab — a searchable list of everything this app can do. Type what you want ("commit", "merge", "push submodule"); commands relevant to what's currently selected are boosted to the top.

          
Git Console tab — run any real git command (with or without typing "git" first) and see its actual output, scoped to wherever you currently are (shown at the top, changeable with "⇄ scope"). As-you-type hints show common flags in plain language, and typos get a "did you mean" suggestion. Commands that look destructive (force push, hard reset, etc.) ask for confirmation first.

        

        

          Remotes
          
Lists configured server locations for the main project and lets you fetch from any of them explicitly. The toolbar's ↓ fetches just the first one; ⇊ ("Fetch all") fetches every configured remote in one go — useful when the project has more than one (a mirror, an upstream…).
